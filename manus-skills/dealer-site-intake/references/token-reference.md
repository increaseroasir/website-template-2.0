# Token Reference — website-template-2.0 (generated)

**Optional sections (TVD-030):** tokens marked `optional-section (CONTROL)` live
inside `<!-- IF:CONTROL -->…<!-- /IF:CONTROL -->` blocks in the HTML. When the
CONTROL token is unset, the build removes the whole section (offer marquee/band/
countdowns, guide band, massage category card, floor-count line, response
promise) — nothing to fill, nothing ships. When CONTROL **is** set, every member
token of that section becomes required (a blank member still fails the gate).
Never invent promo/guide copy to satisfy the validator — leave the control unset.

**Prefilled defaults (TVD-031):** rows with a default value and `required: no` ship
professional dealer-neutral copy baked into the HTML. Leave them out of `tokens.env`
entirely unless the client wants custom wording — the default is template canon and
claim-free. Only the ~60 no-default rows (client facts: identity, contact, images,
real reviews, real stats, SEO titles) must come from intake.

Generated by scanning every `{{TOKEN}}` / `{{TOKEN|default}}` in the
repo's HTML. **328 unique tokens.** "Required" = no `|default`
anywhere it appears, so an unfilled value ships as literal `{{...}}` and
fails the gate. Context legend: text = rendered copy · attribute = inside an
HTML attribute (escape apostrophes; no raw `|` — the pipe parser splits on
it) · meta/title = SEO surface · JSON-LD = structured data (must be real
facts, see content-rules.md).
