## Conflicts / ambiguity calls (reported, not silently resolved)

1. **img width/height vs template reality.** The launch gate requires every
   `<img>` to carry width/height; the template currently has 8 `<img>`
   instances (3 patterns: `PRODUCT_PRIMARY_IMAGE` cards, `VISIT_IMAGE_1/2`)
   without them. A perfectly-hydrated client build will FAIL this row until
   the template adds dimensions — that's a template-repo fix (Law 1), so
   gate.mjs implements the rule as specified and the template gap is logged
   here.
2. **"Exactly one preload per page" vs SITE_MASTER_SPEC.** The master spec
   preloads only LCP heroes; 7 of 11 template pages legitimately have no
   hero preload (financing, contact, thank-you, admin, inventory,
   active-inventory, SLUG). The gate rule as written will FAIL those pages.
   Implemented as specified (launch gate outranks per the stated order after
   the master spec conflict is visual-only, this is mechanical) — but this
   row needs an owner ruling: either add preloads template-wide or amend the
   gate to "≤1, and exactly 1 where a hero image exists."
3. **No Paradise config artifact.** Acceptance asked for a validate demo on
   "the Paradise example config"; none exists (see demo 2). Interpreted as
   the tokenized template config.
4. **In-place hydration.** `scripts/build-config.mjs` rewrites the tree it
   runs in. The skill's build step therefore rsyncs to `clients/<name>/dist/`
   first and runs there; content tokens flow via `tokens.env` environment
   passthrough, which build-config.mjs already supports (`process.env` merge)
   — zero changes to template scripts.
5. **Fingerprint list scope.** The template guard's forbidden-strings list
   (origin business name, city, fairs, phone) was extended with the five
   live tracking/integration IDs plus the origin email, harvested read-only
   from the origin dealer's site. Fingerprints are **base64-encoded** in
   `template-fingerprints.json` (decoded by gate.mjs at runtime) so the
   skill's own files never trip `npm run brand:guard` and the values can't
   be copy-pasted into a build by accident. The city fingerprint stays
   case-sensitive to avoid false hits inside words.
6. **`FINAL_DIAL_IN_AND_LAUNCH_GATE.md` vs `brand:guard`.** The standing
   gate doc (mandated verbatim at repo root by the launch-gate prompt)
   quotes the origin city and phone inside its own grep examples, so
   `npm run brand:guard` now fails on that one file. All skill-pack files
   were scrubbed/encoded to stay clean; the doc itself is user canon and was
   not edited. **Owner ruling needed**: add the doc to the guard's allowlist
   (one-line template-repo change to `scripts/check-template-guard.mjs`,
   which this task was not permitted to touch).
